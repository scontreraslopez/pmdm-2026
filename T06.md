## Introducción

Casi todas las apps son, en el fondo, una lista: chats, correos, productos, canciones, ajustes... En este tema vemos cómo mostrar listas largas que se desplazan, y cómo gestionar el estado de sus elementos sin que se pierda por el camino.

¿Te acuerdas de la tabla de [T03](T03.md#jetpack-compose) que comparaba Views con Compose? En la fila de **listas**, el sistema clásico necesitaba un `RecyclerView`, un `Adapter` y un `ViewHolder`; en Compose basta con un `LazyColumn`. Este tema es esa fila.

> [!IMPORTANT]
> Este tema **no tiene entregable**, pero el [ejercicio propuesto](#ejercicio-propuesto-ludoteca) no es opcional en la práctica: **la ludoteca es el proyecto que en T07 vas a convertir a MVVM**, y ese sí se entrega. Hazlo y guárdalo bien.

La referencia oficial de todo lo que vemos aquí es la guía [Lazy lists and lazy grids](https://developer.android.com/develop/ui/compose/lists). Es de las mejores de la documentación de Compose; tenla a mano.

## 1. Scroll sin listas: verticalScroll

Una `Column` no hace scroll: si su contenido no cabe, lo que sobra queda fuera de la pantalla. Para que lo haga basta con un modificador:

```kotlin
Column(modifier = Modifier.verticalScroll(rememberScrollState())) {
    repeat(100) { Text("Elemento $it") }
}
```

Funciona, pero tiene trampa: la `Column` **compone los 100 elementos**, aunque solo se vean diez. Para un formulario o una pantalla de ajustes no pasa nada. Para el catálogo de una tienda con miles de productos, la app va a ir a pedales.

## 2. LazyColumn y LazyRow

`LazyColumn` es una lista **perezosa** (*lazy*): solo compone los elementos que se ven en pantalla y un pequeño margen. Cuando haces scroll, los que salen de la pantalla **salen de la composición** y entran los nuevos. Esto es importante para el [estado de los elementos](#6-estado-en-listas).

`LazyColumn` es la versión vertical y `LazyRow` la horizontal, con la misma API:

```kotlin
LazyColumn {
    item {
        Text("Mis juegos", style = MaterialTheme.typography.headlineSmall) // Cabecera
    }
    items(juegos) { juego ->
        JuegoCard(juego)
    }
}
```

Hay cuatro formas de añadir contenido:

| Función | Qué añade |
| :--- | :--- |
| `item { }` | Un único elemento: una cabecera, un pie, un separador |
| `items(cantidad) { indice -> }` | `cantidad` elementos; recibes la posición |
| `items(lista) { elemento -> }` | Un elemento por cada elemento de la lista. La más habitual |
| `itemsIndexed(lista) { indice, elemento -> }` | Igual, pero recibes también la posición |

### El contenido no es un composable

Este es el primer error que vas a cometer, así que va aparte. El lambda de `LazyColumn` **no es una ranura** como la de `Column` ([T05 · El contenido es una ranura](T05.md#el-contenido-es-una-ranura)). Es un DSL, `LazyListScope`, que **describe** qué elementos hay. No puedes poner un `Text` suelto dentro: todo va en `item` o en `items`.

```kotlin
LazyColumn {
    Text("Cabecera")        // ❌ No compila: aquí no se pueden llamar composables
    item { Text("Cabecera") } // ✅
}
```

### Espaciado

```kotlin
LazyColumn(
    contentPadding = PaddingValues(16.dp),
    verticalArrangement = Arrangement.spacedBy(8.dp)
) { /* ... */ }
```

- `verticalArrangement = Arrangement.spacedBy(8.dp)`: la separación **entre** elementos.
- `contentPadding`: el margen alrededor de la lista. ¿Por qué no `Modifier.padding`? Porque `Modifier.padding` recorta la zona de scroll: los elementos desaparecen antes de llegar al borde. Con `contentPadding` el margen se respeta al principio y al final, pero al hacer scroll los elementos se desplazan por encima de él hasta el borde de la pantalla.

<!-- IMAGEN: contentPadding frente a Modifier.padding al llegar al final de la lista -->

Para cabeceras que se quedan fijas mientras su grupo hace scroll (una agenda de contactos por letra) existe `stickyHeader { }`.

## 3. El modelo de datos

Una lista de verdad no es de `String`: es de **objetos** con varios datos. Lo habitual es una `data class` para el modelo y algo que haga de fuente de datos:

```kotlin
data class Juego(
    val id: Int,
    @StringRes val titulo: Int,
    @StringRes val genero: Int,
    @DrawableRes val caratula: Int,
    val nota: Int = 0
)

object Datasource {
    val juegos = listOf(
        Juego(1, R.string.elden_ring, R.string.genero_rpg, R.drawable.elden_ring),
        Juego(2, R.string.witcher3, R.string.genero_rpg, R.drawable.witcher3),
        // ...
    )
}
```

- **Por qué un `Int` y no un `String`**: los textos siguen en `strings.xml` (y así se pueden traducir), y se resuelven en la UI con `stringResource(juego.titulo)`.
- **`@StringRes` y `@DrawableRes`** no cambian nada al compilar, pero hacen que Android Studio te avise si pasas un `R.drawable` donde va un `R.string`. Son baratas y evitan errores tontos.
- **`object`**: una clase con una única instancia. Aquí hace de "base de datos" de mentira, hasta que en temas posteriores los datos vengan de una API o de una base de datos de verdad.
- **`id`**: lo vamos a necesitar para la [`key`](#claves-key).

## 4. Cada elemento, una Card

La [`Card` de T05](T05.md#4-card) es el contenedor natural para cada elemento de una lista. El composable del elemento **no tiene estado**: recibe el juego y avisa de los eventos, exactamente como en la [elevación de estado de T04](T04.md#7-elevación-de-estado-state-hoisting):

```kotlin
@Composable
fun JuegoCard(
    juego: Juego,
    onNotaChange: (Int) -> Unit,
    onBorrar: () -> Unit,
    modifier: Modifier = Modifier
) {
    Card(modifier = modifier.fillMaxWidth()) {
        Row(verticalAlignment = Alignment.CenterVertically) {
            Image(
                painter = painterResource(juego.caratula),
                contentDescription = null, // El título de al lado ya dice qué es
                contentScale = ContentScale.Crop,
                modifier = Modifier.size(96.dp)
            )
            Column(
                modifier = Modifier
                    .weight(1f)
                    .padding(horizontal = 16.dp)
            ) {
                Text(stringResource(juego.titulo), style = MaterialTheme.typography.titleMedium)
                Text(stringResource(juego.genero), style = MaterialTheme.typography.bodySmall)
                RatingBar(rating = juego.nota, onRatingChange = onNotaChange, starSize = 24.dp)
            }
            IconButton(onClick = onBorrar) {
                Icon(
                    painter = painterResource(R.drawable.ic_delete),
                    contentDescription = stringResource(R.string.borrar)
                )
            }
        }
    }
}
```

- El `RatingBar` es el de [T05](T05.md#3-ratingbar-un-componente-propio), tal cual.
- `Modifier.weight(1f)` en la columna central hace que ocupe todo el hueco entre la imagen y el botón ([T04 · weight](T04.md#ampliación-modifier-weight)).
- Las carátulas son fotos, así que van en `drawable-nodpi`, como la imagen de fondo de [T03](T03.md#qué-es-un-recurso).

## 5. Cuadrículas

Si los elementos son más visuales que textuales (carátulas, fotos, productos), una cuadrícula aprovecha mejor la pantalla:

```kotlin
LazyVerticalGrid(
    columns = GridCells.Adaptive(minSize = 160.dp),
    contentPadding = PaddingValues(16.dp),
    horizontalArrangement = Arrangement.spacedBy(8.dp),
    verticalArrangement = Arrangement.spacedBy(8.dp)
) {
    items(juegos, key = { it.id }) { juego ->
        JuegoCardVertical(juego)
    }
}
```

- `GridCells.Fixed(2)`: siempre dos columnas. `GridCells.Adaptive(160.dp)`: tantas columnas como quepan de al menos 160dp, así que en horizontal o en una tablet salen más solas. Normalmente quieres `Adaptive`.
- La API de `items` es la misma que la de `LazyColumn`.
- Existen también `LazyHorizontalGrid` y `LazyVerticalStaggeredGrid`, para elementos de alturas distintas (estilo Pinterest).

## 6. Estado en listas

En [T04 · Estado en listas](T04.md#9-estado-en-listas) viste que las listas normales no son observables, que hace falta `mutableStateListOf` o `toMutableStateList()` y que cambiar una propiedad dentro de un elemento no recompone nada. Todo eso sigue valiendo. Con un `LazyColumn` aparecen dos problemas más.

**Primero: `remember` dentro de un elemento se pierde al hacer scroll.** Como el elemento sale de la composición cuando deja de verse, su `remember` se olvida, igual que pasaba en [T04 · UI dirigida por el estado](T04.md#4-ui-dirigida-por-el-estado). Si guardas la nota de cada juego con un `remember` dentro de `JuegoCard`, al bajar y volver a subir las notas han vuelto a cero. Por eso la `JuegoCard` no tiene estado: **el estado de los elementos vive en la pantalla**, en la lista.

<!-- IMAGEN: GIF de una lista perdiendo las notas al hacer scroll, con remember dentro de la Card -->

### Claves: key

**Segundo: la identidad de cada elemento.** Por defecto, Compose identifica cada elemento de un `LazyColumn` por su **posición**. Si borras el segundo, el que era tercero pasa a ser segundo y **hereda lo que el segundo recordaba**: la casilla marcada, el texto a medio escribir, la animación...

La solución es decirle a Compose qué identifica de verdad a cada elemento:

```kotlin
items(juegos, key = { it.id }) { juego -> /* ... */ }
```

La clave tiene que ser **única** (si se repite, la app falla) y **estable** (no puede cambiar mientras el elemento esté en la lista). Un `id` es perfecto; la posición o el título, no.

<!-- IMAGEN: GIF del estado "desplazado" al borrar un elemento sin key -->

### Añadir, borrar y modificar

El patrón completo, con el modelo inmutable de la [sección 3](#3-el-modelo-de-datos):

```kotlin
@Composable
fun LudotecaScreen(modifier: Modifier = Modifier) {
    val juegos = remember { Datasource.juegos.toMutableStateList() }

    LazyColumn(modifier = modifier) {
        items(juegos, key = { it.id }) { juego ->
            JuegoCard(
                juego = juego,
                onNotaChange = { nota ->
                    val i = juegos.indexOfFirst { it.id == juego.id }
                    juegos[i] = juego.copy(nota = nota) // Sustituir, no modificar
                },
                onBorrar = { juegos.remove(juego) }
            )
        }
    }
}
```

Es la **opción B** de T04 §9: `Juego` es una `data class` con `val`, así que no se puede cambiar. Se sustituye por una copia con `copy(nota = nota)`, y de eso la `SnapshotStateList` sí se entera.

Para añadir, `juegos.add(nuevoJuego)`. Si quieres que las altas, bajas y cambios de orden se animen, añade `Modifier.animateItem()` al elemento (necesita `key`).

### El problema que queda abierto

Haz la prueba: pon unas cuantas notas, borra un juego y **gira el móvil**. Las notas vuelven a cero y el juego borrado reaparece.

`rememberSaveable` no sirve tal cual, porque una lista de `Juego` no cabe en un `Bundle` sin hacerla `Parcelable`. Y aunque lo hicieras, la pantalla está mezclando la UI con la gestión de los datos. Lo arreglaremos en T07 sacando esta lista a un **ViewModel**, como se adelantaba en [T04 · Hacia el ViewModel](T04.md#10-hacia-el-viewmodel).

## 7. Controlar el scroll: LazyListState

Para saber dónde está la lista o moverla desde código, se eleva su estado con `rememberLazyListState()`. Un ejemplo típico es el botón de "volver arriba", que solo aparece cuando has bajado:

```kotlin
val listState = rememberLazyListState()
val scope = rememberCoroutineScope()

// Solo cambia cuando cruza el umbral, no en cada píxel de scroll
val mostrarBotonArriba by remember {
    derivedStateOf { listState.firstVisibleItemIndex > 0 }
}

Scaffold(
    floatingActionButton = {
        if (mostrarBotonArriba) {
            FloatingActionButton(onClick = {
                scope.launch { listState.animateScrollToItem(0) }
            }) {
                Icon(
                    painter = painterResource(R.drawable.ic_arrow_upward),
                    contentDescription = stringResource(R.string.volver_arriba)
                )
            }
        }
    }
) { innerPadding ->
    LazyColumn(state = listState, modifier = Modifier.padding(innerPadding)) { /* ... */ }
}
```

- `rememberLazyListState()` sigue el mismo patrón `rememberXxxState()` que el `rememberScrollState()` de la [sección 1](#1-scroll-sin-listas-verticalscroll).
- `animateScrollToItem` es una función `suspend`, igual que `showSnackbar` en [T05](T05.md#snackbar): mismo `scope`, misma explicación.
- **`derivedStateOf`**: `firstVisibleItemIndex` cambia sin parar mientras haces scroll. Si lo lees directamente, el `Scaffold` se recompone en cada cambio. Con `derivedStateOf` solo se recompone cuando el `Boolean` pasa de `false` a `true` o al revés. Es la recomposición inteligente de [T04](T04.md#2-composición-y-recomposición) en un caso en el que se nota.

## 8. Errores frecuentes

- **`LazyColumn` dentro de una `Column` con `verticalScroll`**: la app falla con *"Vertically scrollable component was measured with an infinity maximum height constraints"*. No se pueden anidar dos scrolls en la misma dirección. Si necesitas una cabecera, usa `item { }` dentro del propio `LazyColumn`.
- Poner composables sueltos dentro de `LazyColumn` sin `item { }`.
- No usar `key` y borrar elementos.
- Guardar el estado del elemento con `remember` dentro de `items`: se pierde al salir de la pantalla.
- Usar `mutableListOf()`, o modificar una propiedad de un elemento en vez de sustituirlo.
- `Modifier.fillMaxHeight()` o `fillMaxSize()` en un elemento: en una lista vertical la altura disponible es infinita. Si quieres un elemento del alto de la pantalla, existe `Modifier.fillParentMaxHeight()`.
- Ordenar o filtrar la lista dentro del `items`, en cada recomposición. Hazlo fuera: `remember(juegos) { juegos.sortedBy { it.nota } }`.

## Ejercicio propuesto: ludoteca

Vas a hacer una app con tu colección de videojuegos: una lista de tarjetas con la carátula, el título, el género y tu nota, en la que puedes puntuar y borrar juegos.

> [!IMPORTANT]
> **No se entrega en T06, pero es la base del entregable de T07**, donde la convertirás a MVVM sobre el mismo repositorio. Termínala y marca la versión con el tag `v1.0`.

Para que no pierdas el tiempo en lo que ya sabes hacer, partes de un proyecto **medio montado**: el modelo, los datos, las imágenes y el `Scaffold` ya están. Lo tuyo es la lista y su estado.

### Pasos

1. En GitHub, pulsa **Use this template** en el repositorio de partida y crea un repositorio **privado** llamado `ludoteca` en tu organización. No lleva el prefijo `T06-` porque el proyecto sigue vivo en T07.
2. Clónalo, ábrelo en Android Studio y comprueba que arranca: verás la `TopAppBar` y una pantalla vacía.
3. Pega tu `RatingBar` de T05 en `RatingBar.kt`.
4. Añade **al menos tres juegos más** a `Datasource`, elegidos por ti: carátula en `drawable-nodpi`, título y género en `strings.xml`.
5. Implementa `JuegoCard` ([sección 4](#4-cada-elemento-una-card)): carátula, título, género, `RatingBar` y botón de borrar. **Sin estado**.
6. En `LudotecaScreen`, muestra los juegos en un `LazyColumn` con `contentPadding`, separación entre tarjetas y `key` ([secciones 2](#2-lazycolumn-y-lazyrow) y [6](#claves-key)).
7. Haz que la nota se pueda cambiar desde la tarjeta y que **se mantenga al hacer scroll**: el estado va en la pantalla, y se cambia con `copy` ([Añadir, borrar y modificar](#añadir-borrar-y-modificar)).
8. Al pulsar el botón de borrar, pide confirmación con un [`AlertDialog`](T05.md#5-diálogos). Ojo: hay **un** diálogo para toda la pantalla, no uno por tarjeta. Guarda en el estado **qué juego** se quiere borrar (`var juegoABorrar by remember { mutableStateOf<Juego?>(null) }`) y muestra el diálogo si no es `null`.
9. Todos los textos en `strings.xml`.
10. En el `README.md` del repositorio, responde en dos líneas: *¿Qué pasa con las notas y los juegos borrados al girar el móvil? ¿Por qué?* Es la pregunta con la que arranca T07.
11. Haz commits a lo largo del ejercicio y, al terminar, crea el tag **`v1.0`** y súbelo (`git push origin v1.0`).

### Mejoras opcionales

- Un `IconButton` en las `actions` de la `TopAppBar` que cambie entre lista y cuadrícula ([sección 5](#5-cuadrículas)). La vista elegida sobrevive al giro con `rememberSaveable`.
- Un FAB de "volver arriba" que solo aparezca al hacer scroll ([sección 7](#7-controlar-el-scroll-lazyliststate)).
- Ordenar por nota o por título desde la `TopAppBar`, sin ordenar dentro del `items`.
- `Modifier.animateItem()` para que los juegos borrados desaparezcan con animación.
